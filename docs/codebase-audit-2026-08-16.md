Python curriculum, CI and infrastructure, the pricing surfaces, and the security and
accessibility posture), each reader's findings then passed to a separate adversarial

21 land at medium severity; the rest are low.**

No finding survived at high severity. Four were raised as high and the verification pass

## How to read a verdict

| Verdict | Means |
|---|---|
| **Confirmed** | A verification pass opened the cited file and saw it. |
| **Partly true** | The observation is real but the original framing overstated it. The correction is in the Verifier line — read that before acting. |
| **Refuted** | It did not survive. Kept in the record so the same finding is not re-raised. |

Severity was set by the verification pass, not by the reader that raised the finding;
several were trimmed on contact with what actually happens in production.

### Thirty of these were verified twice, and the two passes disagreed thirteen times

An infrastructure error killed three verifiers mid-run. Re-running re-verified three
dimensions that had already completed, so 30 of the 60 findings carry two *independent*
adversarial verdicts. **They disagreed on 13 of those 30** — a 43% disagreement rate.

That is worth knowing before you trust a severity in this document:

- **Substance was stable.** No finding was confirmed by one pass and refuted by the other.
  The single status flip was one finding moving between *refuted* and *partly true*.
- **Severity was not.** All 13 disagreements were about the medium/low line, in both
  directions. The medium/low boundary here is a judgement call, not a measurement.
- **This document takes the union** — where the two passes differ, the *more severe*
  verdict is shown and the finding is marked ⚖. Taking the union rather than the last
  answer moves the medium count from 17 to 21.

Read a lone severity as one reviewer's opinion. Read a ⚖ as two reviewers who looked at
the same code and landed in different places, which usually means the finding is real and
the question is only whether it is worth your afternoon.

## Resolved while preparing this document

- **The `no-commercial-terms` guard had a hole this report walked straight through.**
  Its `markup multiple over cost` pattern required the literal token `Nx cost` and capped
  the multiplier at one decimal place, so a markup written against a billable *unit* rather
  than the word "cost" passed clean. The pattern now also matches a multiple attached to a
  per-task/shot/token/credit/run rate, and a second pattern catches the same disclosure
  written as division. Both are locked by a 21-case table of must-trip and must-spare
  strings, because the must-spare half matters just as much: Tailwind's `2xl`, HTTP `5xx`,
  CLAUDE.md rule 10's "3x the monthly grant" and Amazon's own published "1.10x Anthropic
  list" are all legitimate and none may trip.
- **Account identifiers are out of the docs.** `docs/account-migration-runbook.md`,
  `docs/billing-cutover-runbook.md`, `docs/eval-implementation-plans.md` and
  `lambda/tutor/README.md` now reference `$SRC_ACCOUNT` / `$DST_ACCOUNT` /
  `$ORG_MGMT_ACCOUNT` / `$SRC_PROFILE_ID` / `$GOOGLE_CLIENT_ID`, resolved by an
  `aws organizations` block at the top of the migration runbook, so every command stays
  copy-pasteable. Two literals were deliberately left in place: the `expectedAccountId`
  in `scripts/founding-credit/cohort-2026-08.json` is a spend guard that aborts issuance
  from the wrong account, and `lambda/tutor/policy.json` is a live IAM document.

### How it actually works

Published pricing lives in web/src/lib/pricing.ts (CREDIT_USD peg, HARDWARE_RATES, SIMULATOR_RATES, TUTOR_RATES, TIERS with i18n key arrays rather than inline copy) and is mirrored server-side by CATALOG in lambda/stripe/index.mjs, which is the only writer of credits and tier via Stripe-signed webhooks under a DynamoDB TransactWriteItems idempotency pattern. The /pricing page is a thin server component whose metadata is hand-written; all rendering happens in web/src/components/pricing/pricing-page-content.tsx, which resolves tier taglines, feature bullets and footnotes through translate() against web/src/i18n/locales/{en,es}.ts. Two metered surfaces exist in code but not in deployment: lambda/tutor (tier-gated ROSTER, reserve-before-stream via maxCreditsFor, settle on real Bedrock usage including cache read/write multipliers) and lambda/qpu (LIFETIME_CAP_MICROS = 0, an effectiveCap > 0 guard, and a 402 refusal when no wallet table is configured). Both stacks ship with UserPoolId and WalletTableName empty, so nothing debits anything today and every curriculum QPU submit returns 402. Honesty is guarded by three mechanisms: pricing.test.ts (published rates cover provider list rates; tier keys resolve in both locales), pricing-page.test.tsx (UNDELIVERABLE_CLAIMS regexes over rendered DOM in both locales), and web/__tests__/infra/no-commercial-terms.test.ts (six numeric spread patterns over every source file in the repo). The gap this review found is that the guards cover the pricing page's rendered DOM and numeric spread patterns, but not page metadata, not README.md, not PRODUCT.md's prose, not hardcoded English strings in the QPU and playground panels, and not the TIERS-to-CATALOG relationship they are documented to protect.

### Done well

- web/src/lib/pricing.ts:235 replaced inline English bullets with i18n key arrays after an audit found the card rendered `pricingUi.{tier}F{i}` and never read the array — the copy-honesty tests had been passing vacuously. The fix is documented in place, and the per-tier bullet count is deliberately uneven (Plus 3, Pro 2) rather than padded back to five with invented benefits.
- web/__tests__/app/pricing-page.test.tsx:307-330 asserts on rendered DOM in both locales with negation-aware lookbehinds, including a Spanish arm that was corrected after "no/nada/tampoco/nunca se mide" matched as a present-tense metering claim — a class of i18n false positive most guards never reach.
- lambda/qpu/qpu-core.mjs:515 pairs the zero lifetime cap with an explicit `effectiveCap > 0` guard and documents why the cap alone is insufficient: the allowance leg's `attribute_not_exists(spentMicros)` condition would let a cap-0 learner's first submit through as one free real-money run.
- web/__tests__/infra/no-commercial-terms.test.ts:103-106 guards its own walker with `expect(files.length).toBeGreaterThan(200)`, so the scan cannot silently degrade to zero files and pass forever — and the patterns are narrow enough that "the margin rule", "Ask the margin" and CACHE_*_MULTIPLIER do not trip.

## The money path

10 findings, 2 at medium.

### How it actually works

Five SAM stacks share one DI-core pattern: each `*-core.mjs` exports `createHandlerCore({deps})` so the money path unit-tests offline under `node --test`, and a thin `index.mjs` wires real AWS clients from env. `lambda/stripe/index.mjs` is the only writer of credits and tier: three Cognito-JWT routes (`/checkout`, `/portal`, `/wallet`) plus a public `/webhook` authenticated by `stripe.webhooks.constructEventAsync`, with every wallet mutation running through `applyOnce()` as a TransactWriteItems whose leg 0 is a conditional `EVENT#<id>` put (idempotency), leg 1 the `WALLET#<sub>` update, and optional leg 2 a `RECEIPT#<paymentIntent>` row that makes refunds findable after Basil removed `Charge.invoice`. `lambda/qpu/qpu-core.mjs` gates real Braket spend behind email verification plus a server-minted cost-estimate credential (`CRED#<sub>`), then commits a four-leg atomic reservation (funding source, `DAY#` global cap, idempotency put, `KILL` ConditionCheck) *before* `CreateQuantumTask`, with a compensating `releaseReservation` only on submit failure and `reconcile.mjs` polling Braket every 5 minutes to keep or refund the charge. `lambda/tutor/index.mjs` streams Bedrock ConverseStream through a Function URL, verifies the ID token in-process (`aws-jwt-verify`) for paid models, reserves the worst case via `maxCreditsFor` before the call, and settles down to real `metadata.usage` after — pricing `cacheReadInputTokens`/`cacheWriteInputTokens` explicitly so the cache prefix isn't a giveaway. `lambda/sync` is a deliberately dumb versioned per-user KV with OCC; `lambda/review-email` scans that table, gates on an opt-in prefs table, and sends via SES behind a sandbox check. Both the QPU wallet debit and the tutor wallet debit carry the same `clawbackOwedCredits = 0` guard, which is where several of the findings below converge.

### Done well

- lambda/stripe/index.mjs:255-267 branches TransactWriteItems cancellations PER LEG by index (EVENT_LEG/WALLET_LEG/RECEIPT_LEG) rather than on "the first reason" — the comment explains precisely why conflating them would read an OCC loss as a replay and silently drop a clawback. The reclaim() arithmetic at :505 is absolute (target from Stripe's cumulative amount_refunded) rather than incremental, so a stale or out-of-order delivery is a no-op even after the 30-day EVENT# marker has TTL'd away.
- lambda/qpu/qpu-core.mjs:515 — `const fitsAllowance = effectiveCap > 0 && ...`. The `effectiveCap > 0` term is load-bearing independently of the arithmetic, because the allowance leg's condition permits a first submit via `attribute_not_exists(spentMicros)`; without it a cap-0 learner would get exactly one free real-money run. qpu-core.test.mjs W1/W2/W5 pin all three halves of that.
- lambda/tutor/tutor-billing.mjs:133-150 prices cacheReadInputTokens and cacheWriteInputTokens explicitly, having verified that `usage.inputTokens` is the uncached remainder (5,545-token prompt reporting inputTokens=14). Billing only inputTokens would have stopped charging for ~99.7% of the prompt the moment the cachePoint was added, with no visible symptom.
- The template tests pin CloudWatch metric-filter patterns to literal strings that must still appear in the handler source (lambda/qpu/template.yaml:551 '"qpu-reconcile: orphaned row"', lambda/stripe/template.yaml:300 '"credits NOT reclaimed"'), so editing a log line reddens a test instead of silently disconnecting the only alarm that can see a 200-returning money failure.

#### 1. A reinstated dispute returns the credits but never clears the debt it created, permanently locking the learner out of every metered surface

#### 3. clawbackOwedCredits has no floor and is computed from a read outside the transaction, so concurrent purchases can drive it negative and wedge the wallet

**Claim.** `splitAgainstDebt` does a plain `GetItemCommand`, computes `applied = Math.min(owed, credits)` and returns `owedCredits: -applied`, which `applyOnce` then applies as an unconditional `ADD clawbackOwedCredits :owed`. **Verifier.** The mechanics check out: splitAgainstDebt (index.mjs:420-428) does a plain GetItemCommand and returns `owedCredits: -applied`, and applyOnce's wallet leg (242-249) carries UpdateExpression/ExpressionAttributeValues with NO ConditionExpression — unlike the receipt leg in reclaim, which does have an OCC guard (`${field} = :seen`, 528-537). ### How it actually works

Routing is a static export (`next.config.ts` sets `output: "export"`, no images/rewrites), producing ~110 flat `.html` files plus sibling `.txt` RSC flight segments under `web/out/`. Only four routes do real server work at build time: `learn/[section]` (reads `../<dir>/GUIDE.md` and `GUIDE.es.md` off disk via `lib/content.ts`), `glossary` and `glossary/[term]`, `founding-ten/[badge]`, plus `sitemap.ts`/`robots.ts`; everything else is a thin server shell wrapping a `"use client"` component, and `app/workspace/page.tsx` is itself a client module. Fenced ```q* blocks are intercepted in `markdown-components.tsx`'s `pre` override, matched against `WIDGET_LANGS`, and resolved by `widget-fence.tsx`, which holds a 35-entry registry of `dynamic(..., {ssr:false})` widgets behind an IntersectionObserver approach gate and a single shared error boundary. Learner state is localStorage-only, namespaced per owner by `progress-owner.ts` (anon === the flat canonical space), broadcast on one `qc-progress` channel, read everywhere through `useSyncExternalStore`, and pushed to DynamoDB by `sync-client.ts` (pull → `progress-merge.mergeSnapshots` → apply → versioned PUT with one 409 retry, plus a keepalive exit flush). The `*-schema.ts`/`*-grade.ts` pairs are a deliberate uniform convention — each kind exposes `parseX`, `xTruth`, `gradeX`, `xReviewAnswer`, and `rep-schema.ts` dispatches all six — not accidental copy-paste, though nothing type-enforces the shape and adding a seventh kind requires edits in seven registries (`CardKind`, `KIND_LABELS`, `LIVE_WIDGETS`, `WIDGET_LANGS`, `WIDGETS`, `REP_KINDS`, the `rep-schema` switch), and the optional-field validation has genuinely drifted between them.

## Security and accessibility

10 findings, 1 at medium.

### How it actually works

Quantum Learner is a Next.js 16 static export (`output: \"export\"`, no server) deployed to AWS Amplify, fronted by a root-level `customHttp.yml` that is the only response-header surface, plus five SAM stacks in `lambda/` (tutor, sync, qpu, stripe, review-email). Auth is Cognito via aws-amplify v6, isolated in a lazily-loaded `AmplifyAuthBridge` that deliberately relocates tokens from the v6 default localStorage to per-tab `sessionStorage` because the same-origin Pyodide lab can read localStorage. `AuthWall` gates every non-funnel route on client state and its own comment correctly identifies itself as an access gate rather than a confidentiality boundary — under static export the React Flight payload for `/learn/*` is recoverable from the HTML, which the team mitigates with per-route `robots: {index:false}` rather than pretending otherwise. Untrusted-input surfaces are narrow and clean: the only `dangerouslySetInnerHTML` in `web/src` is a fixed locale-bootstrap literal in `layout.tsx`, `rehype-raw` is absent, `KATEX_OPTIONS` leaves `trust` at its safe default, and the tutor's streamed model output is rendered into a plain `<p>` text sink rather than through a markdown renderer. Learner Python runs in a dedicated worker (`web/public/pyodide.worker.js`) with a fresh namespace per run and a client-side `terminate()` timeout, with the CDN fallback bootstrap hand-verified against a sha384 pin since `importScripts` cannot carry SRI. Server-side identity is verified everywhere it matters — `aws-jwt-verify` in the streaming tutor Function URL, API Gateway Cognito JWT authorizers elsewhere, and a single explicitly-`Authorizer: NONE` Stripe webhook route authenticated by HMAC. Accessibility is unusually deliberate: no click handlers on non-interactive elements anywhere, a documented Monaco keyboard-escape for WCAG 2.1.2, a full ARIA menu pattern in `account-menu.tsx`, and reduced-motion coverage that even handles scroll-timeline animations the global duration override cannot neutralize. The gaps that remain are concentrated in configuration (dev origins on production auth), route-level error handling (none at all), and i18n reaching the sr-only layer.

### Done well

- `web/src/components/auth/amplify-auth-bridge.tsx` overrides Amplify v6's default token storage with `cognitoUserPoolsTokenProvider.setKeyValueStorage(amplifyTokenStorage)` specifically so Cognito tokens live in per-tab sessionStorage rather than localStorage, which the same-origin Pyodide lab can read — a threat most teams never notice, named in the comment.
- `web/public/pyodide.worker.js` isolates learner code off the main thread with a fresh `pyodide.toPy({})` namespace per run, and `importScriptWithIntegrity` (lines 50-67) hand-computes a SHA-384 digest before executing the CDN fallback bootstrap, restoring the SRI guarantee `importScripts` cannot provide.
- Money paths never trust the client: `lambda/tutor/index.mjs:414` verifies the Cognito ID token in-Lambda with `aws-jwt-verify` because a streaming Function URL has no authorizer, `lambda/stripe/index.mjs:728` HMAC-verifies the one public route, and `lambda/qpu/qpu-core.mjs:260` recomputes the cost answer server-side (`if (answerCents !== correctCents(shots))`) rather than accepting the learner's figure.
- `web/src/app/globals.css` gets reduced motion right where it is genuinely hard — view-timeline animations at lines 669-693 are wrapped in an explicit `prefers-reduced-motion: no-preference` gate because they are scroll-mapped and the global `animation-duration: 0.01ms` override would not neutralize them, and the reduce block adds `animation-iteration-count: 1` so infinite animations freeze instead of sampling random frames.

## Python, qcsim, and the curriculum

10 findings, 2 at medium.

### How it actually works

The Python side is three cooperating layers. `lib/` is a small, heavily-documented toolkit (circuits, feature maps, ansätze, Hamiltonians, cost, results, visualization) whose modules validate inputs fail-loud and keep `braket.aws` behind a lazy `__getattr__` so the whole package imports in a browser; `lib/hardware/devices.py` is the single source of truth for billable device ARNs, gate-capability, allowlist status and per-device shot bounds, and it derives the printed cost estimate from `lib/utils/cost.py::PRICING` so a billable submit cannot skip the cost gate. `qcsim/` is a ~850-line pure-NumPy stand-in that registers itself as `braket`, `braket.circuits` and `braket.devices` when real Braket is absent; it is unusually faithful — a single `_GATE_SPECS` registry drives matrices, Braket's exact `operator.name` capitalization, diagram glyphs and the parity suite's coverage; qubit compaction, `measured_qubits` in original labels, greedy-moment `depth`, adjoint labelling, float-qubit-index `TypeError`, backend-name validation and global-RNG independence are each diffed against the installed SDK. `tests/` (28 files) is organised as tiers: unit tests over `lib/`, generated cross-language fixtures (`cost.json`, `gates.json`, `h2.json`) locked from both sides, a prose drift guard that derives valid dollar figures from `PRICING`, a static AST contract for browser-runnable notebooks plus headless execution of every one under qcsim, a three-notebook sample under the real SDK, and a solutions harness that runs every notebook twice (with canonical answers under `QL_GRADING_STRICT=1`, and unsolved). `scripts/validate_runnable.py` generates `web/src/lib/content-manifest.json`, the single catalog the web app and the Run button read, with a `--check` drift gate in CI. Solutions coverage is complete: 45 notebooks, 45 files under `tests/solutions/`. The weak seams are all at process boundaries — where a test believes it forced qcsim but did not, where a fixture seeds a process the notebook kernel never sees, and where a code path (the Hybrid Job entry points) is executed by nothing in CI.

### Done well

- tests/test_qcsim_parity.py is the strongest file in the repo: it diffs qcsim against the installed amazon-braket-sdk on object shape (qubit_count, bitstring width, instruction targets, measured_qubits, depth, every gate's operator.name including through .adjoint(), partial target_mapping, qubit-index type validation, backend names, global-RNG independence), compares state vectors elementwise at atol=1e-12 rather than by overlap so phase conventions cannot drift, and enforces structurally that every public gate method has a registry row and appears in the all-gates parity circuit.
- tests/test_statevector_helper.py:132-161 exercises the qcsim engine in a real subprocess and asserts `Circuit.__module__.startswith('qcsim')` before trusting the result — the correct isolation pattern, present in the suite and simply not applied to the fence test.
- tests/test_qpu_devices.py locks the Node spend ledger to the Python cost model with no runtime link between them: it parses lambda/qpu/qpu-core.mjs for DEVICE, DEVICE_ARN, DEVICE_REGION, IQM_PER_TASK_MICROS, IQM_PER_SHOT_MICROS and LIFETIME_CAP_MICROS and asserts each against lib.hardware.DEVICES / lib.utils.cost.PRICING, including that the `effectiveCap > 0` guard string still exists.
- lib/ml/feature_maps.py's Möttönen amplitude encoder is genuinely correct, not just plausible: I ran it through lib/utils/statevector on [1,2,3,4], [0.5,0.1,0.2,0.9], [1,0,0,0], [1..8] and [3,1] and the prepared amplitudes match f/||f|| to 2.5e-16 with zero imaginary part.

#### 8. The prose pricing guard's amount regex cannot see any dollar figure of $1,000 or more written without a comma

**Verifier.** Reproduced exactly against the module at tests/test_pricing_prose.py:86. `extract_amounts('a stale total of $4890 per run')` -> [], `extract_amounts('$1234.56 per job')` -> [], while the comma form `$4,890` -> [(4890.0, ...)]. ## Method

Six readers ran in parallel, each given one subsystem, CLAUDE.md's rules, and an
instruction to ground every claim in a file it had actually opened. Each reader's output
then went to a separate agent instructed to *refute* it — to check the quoted evidence
against the file, to look for the guard or caller the reader missed, and to reject
generic best-practice advice with no concrete failure mode. Findings that contradicted a
deliberate decision recorded in CLAUDE.md ("the storefront stays closed",
"`WalletTableName` stays empty on purpose") were refuted on those grounds.

Severities in this document are the verifier's, not the reader's.
